COGNI IA

Uma ponte entre o conhecimento complexo e o público geral — do conhecimento complexo à clareza. Plataforma de estudos para ENEM e vestibulares em que a IA é uma camada que amplia o potencial de quem estuda, não um fim em si.

15 fases implementadas Next.js 14 · Supabase · Vercel freemium — R$ 0 / R$ 14,90 mês roda em modo demonstração sem chaves

O produto

Uma plataforma completa, montada em módulos que se somam

Cada fase é um módulo independente que consome as anteriores sem modificá-las. O resultado é um monólito modular: web responsiva, banco Postgres com segurança por linha (RLS), IA desacoplada atrás de uma interface única e chave que nunca chega ao navegador.

Para quem estuda

  • Biblioteca ENEM curada — resumo rápido (grátis) e completo (Premium), com diagramas autorais
  • Tutor de IA que explica passo a passo, gera resumos e questões no estilo da banca
  • Correção de redação por competência (ENEM, FUVEST e outras), com banco de erros recorrentes
  • Progresso, pontos fracos, sequência de estudo, conquistas e um "plano de hoje" que se adapta
  • Comunidade de estudos moderada — sem virar rede social

Para operar o negócio

  • Painel admin: usuários, biblioteca, blog, monetização, moderação, saúde, consumo de IA, segurança
  • Assinaturas via Mercado Pago (cartão, Pix, boleto) + cupons + anúncios controlados
  • Fila de jobs, cache, logging estruturado e custo de IA por modelo
  • LGPD: consentimento, exportação e exclusão de dados, 2FA, auditoria
  • Modo de lançamento (lista de espera / manutenção) sem novo deploy

Arquitetura

IA em cinco camadas, como pede a base

A requisição de IA carrega finalidade, contexto permitido, versão do prompt, modelo e limites. A resposta passa por validação de formato, moderação e regras de abstinência. A chave do provedor nunca chega ao navegador.

  1. Entrada e sessão — autenticação, plano, limites de uso, rate limit, contexto do aluno.
  2. Orquestração de prompt e modelo — lib/ai/routing.ts estima a complexidade e roteia; resilient.ts dá retry, fallback para o mock e telemetria.
  3. Recuperação de conteúdo aprovado — a biblioteca curada entra no prompt; o tutor só recomenda links reais do catálogo.
  4. Validação, moderação e apresentação — parsing de JSON, heurística + IA de moderação, regras de "não afirmar certeza absoluta".
  5. Observabilidade e auditoria — ai_calls (tokens, duração, custo por modelo), system_logs, security_events, painéis /admin/saude, /admin/consumo, /admin/ia.

Stack de baixo custo

  • Next.js 14 (App Router, RSC, Server Actions) + TypeScript estrito
  • Supabase — Postgres, Auth, Storage, RLS; migrações versionadas
  • Vercel (região gru1, São Paulo) + cron a cada 5 min
  • Cache/rate-limit: memória do processo ou Upstash Redis
  • IA: OpenAI (texto) + Gemini (visão) — mock offline sem chave
  • Pagamentos: Mercado Pago — modo simulado sem token

Roteamento de modelo (Fase 15)

  • chat: modelo forte quando a complexidade ≥ 70, senão o econômico
  • summary ≥ 55 · questions ≥ 60
  • essay: sempre o modelo forte (alta aposta)
  • memory: sempre o econômico (destilação)
  • Override editável em site_config.model_routing
  • Princípio da base: "não enviar todas as mensagens ao modelo premium"

Ordem para o primeiro deploy

Detalhe completo em docs/fase-13-setup.md e docs/producao-checklist.md.

  1. Instalar e verificar — npm install, depois npm run check (typecheck + lint + testes). Commitar o package-lock.json.
  2. Supabase — criar o projeto em sa-east-1; rodar as migrações 0001→0013 no SQL Editor, em ordem.
  3. Storage — criar os buckets avatars, blog (públicos), essays, materials, exports (privados).
  4. Seed — npm run seed:biblioteca; inserir o primeiro administrador em app_admins.
  5. Vercel — importar o repositório; definir as variáveis de ambiente (obrigatórias: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY; recomendadas: SUPABASE_SERVICE_ROLE_KEY, NEXT_PUBLIC_APP_URL, CRON_SECRET, APP_ENCRYPTION_KEY, MERCADOPAGO_*).
  6. Domínio e integrações — apontar cogniai.com.br; redirect do Supabase Auth para /auth/callback; webhook do Mercado Pago; o cron de vercel.json já chama /api/cron a cada 5 min.
  7. Smoke em produção — cadastro, login, chat, envio de redação, checkout, /admin/saude no verde.

Sem chaves externas o site funciona em modo demonstração: IA mock, checkout simulado, cache em memória. Cada variável de ambiente preenchida liga um recurso real — o boot registra o que está faltando (lib/env.ts).

Formas limpas e geométricas, foco absoluto na legibilidade. Voz curiosa, acessível, autoritária mas amigável. Referência em docs/marca.md e fonte única em lib/brand.ts.
